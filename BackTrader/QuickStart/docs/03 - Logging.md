Одна из важнейших задач в автоматической торговле - это ведение журнала (лога).
В лог можно записывать не только точки входа в позицию и выхода из нее, но и любые значимые для нас события. Например, получение котировок от брокера, прохождение логики торговой системы и многое другое.
Задача лога - документировать события так, чтобы они не прошли мимо нашего взгляда.

Для лога в python судествует встроенная библиотека logging. Импортируем ее.

```python
import logging
```

У каждого лога есть свое название. Это удобно. Когда у нас будет работать несколько логов одновременно, мы по названию точно сможем определить какая информация от какого лога пришла. Для нашего примера назовем лог Logging.

```python
logger = logging.getLogger('Logging')  # Будем вести лог
```

## Настройка лога
Лог можно гибко настроить через **logging.basicConfig**.

Формат (format) лога показывает, какие поля выводить в сообщение лога. 
- Дата и время события (asctime)
- Название лога (name)
- Уровень события (levelname). Уровни событий будут расписаны ниже
- Сообщение (message)

Дату и время события (datefmt) можно выводить в привычном нам формате. Например, последняя секунда 2025 года будет показана как 31.12.2025 23:59:59

### Уровни событий
Не обязательно вести лог всех уровней (level) событий. Можно указать явно, от какого типа вести лог.
- DEBUG - отладочная информация для разработки и тестирования. Помогает понять как появилось то или иное значение
- INFO - успешное выполнение операции. Например, подключились к брокеру
- WARNING - операция не была выполнена успешно, но логика кода это учла и внесла необходимые корректировки. Код может продолжать исполняться в штатном режиме. Например, если нет нужного файла, то он создается
- ERROR - операция завершена с ошибкой. Например, пропал интернет. Вариант решения ошибок - подождать и выполнить операцию снова
- CRITICAL - возникла критическая ситуация, которая требует немедленно остановить торговую систему

Обычно, для реальной торговли устанавливают уровень INFO. Тогда в логе будут события типа INFO/WARNING/ERROR/CRITICAL.
Для отладки и тестирования торговых систем полезно установить уровень DEBUG. Тогда в лог попадут все события от DEBUG до CRITICAL.

## Куда выводить лог
Также нужно указать, куда выводить лог (handlers). Самые распространенные это файл (FileHandler) и экран/консоль (StreamHandler). У файла указываем имя Logging.log и кодировку utf-8.

```python
    logging.basicConfig(format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',  # Формат сообщения
                        datefmt='%d.%m.%Y %H:%M:%S',  # Формат даты
                        level=logging.DEBUG,  # Уровень логируемых событий NOTSET/DEBUG/INFO/WARNING/ERROR/CRITICAL
                        handlers=[logging.FileHandler('Logging.log', encoding='utf-8'), logging.StreamHandler()])  # Лог записываем в файл и выводим на консоль
```

## Московское время
Мы все живем в разных часовых поясах. А МосБиржа работает по московскому времени. Можно ли сделать так, чтобы лог записывался не по местному, а по московскому времени?
Да, можно. Для этого сконвертируем дату и время лога. Конвертация простая, ее можно сделать в 1 строчку кода. Поэтому можно использовать lambda функцию.
Мы возьмем текущее локальное время события, переведем его в московское время, и возьмём в структурированном виде timetuple.

```python
from datetime import datetime
from zoneinfo import ZoneInfo  # ВременнАя зона

    logging.Formatter.converter = lambda *args: datetime.now(tz=ZoneInfo('Europe/Moscow')).timetuple()  # В логе время указываем по МСК
```

## Создание событий лога
Теперь можно создавать события лога. В базовом примере можно заменить print из основного кода на событие отладки DEBUG.

```python
    logger.debug('Стартовый капитал')
    logger.debug('Конечный капитал')
```

Также перепишем функцию get_cash_value. Заменим в ней print на информационное событие INFO.

```python
def get_cash_value():
    cash = cerebro.broker.getcash()  # Свободные средства
    value = cerebro.broker.getvalue()  # Стоимость портфеля
    logger.info(f'Свободные средства : {cash}')
    logger.info(f'Стоимость позиций  : {value - cash}')
    logger.info(f'Стоимость портфеля : {value}')
```

Вы можете поставить событие любого типа для лога в коде. Не ставьте лог на каждой строчке кода. Ставьте их там, где требуются пояснения, приходит важная информация, или где возникают проблемы. 

Полный код примера:

```python
import logging
from datetime import datetime
from zoneinfo import ZoneInfo  # ВременнАя зона

import backtrader as bt


logger = logging.getLogger('Logging')  # Будем вести лог


def get_cash_value():
    cash = cerebro.broker.getcash()  # Свободные средства
    value = cerebro.broker.getvalue()  # Стоимость портфеля
    logger.info(f'Свободные средства : {cash}')
    logger.info(f'Стоимость позиций  : {value - cash}')
    logger.info(f'Стоимость портфеля : {value}')


if __name__ == '__main__':  # Точка входа при запуске этого скрипта
    logging.basicConfig(format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',  # Формат сообщения
                        datefmt='%d.%m.%Y %H:%M:%S',  # Формат даты
                        level=logging.DEBUG,  # Уровень логируемых событий NOTSET/DEBUG/INFO/WARNING/ERROR/CRITICAL
                        handlers=[logging.FileHandler('Logging.log', encoding='utf-8'), logging.StreamHandler()])  # Лог записываем в файл и выводим на консоль
    logging.Formatter.converter = lambda *args: datetime.now(tz=ZoneInfo('Europe/Moscow')).timetuple()  # В логе время указываем по МСК

    cerebro = bt.Cerebro()  # Инициируем "движок" BackTrader
    logger.debug('Стартовый капитал')
    get_cash_value()  # Отображаем статистику портфеля до запуска ТС
    cerebro.run()  # Запуск ТС. Пока ее у нас нет
    logger.debug('Конечный капитал')
    get_cash_value()  # Отображаем статистику портфеля после запуска ТС
```
